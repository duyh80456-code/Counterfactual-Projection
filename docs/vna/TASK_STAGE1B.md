## 3. T4×2 throughput optimization (must not change the math or break paired comparison)

Measure first, then optimize; report before/after epoch time on CUDA if available, otherwise
justify by reasoning and make every optimization a flag with the safe default documented.
- Kaggle has ~4 vCPUs: CPU augmentation of batch-64 CIFAR is the likely bottleneck. Add an option
  `--gpu-data` that keeps CIFAR train uint8 on GPU and applies RandomCrop(32, pad 4) + horizontal
  flip on GPU, driven ONLY by the per-arm training generator (identical sequence across arms, no
  global RNG). Same for augmented VNA/statistics batches with their own dedicated generators. Test
  that the CPU fallback of this path is deterministic and that two arms get identical batches.
- `torch.backends.cudnn.benchmark=True`, `channels_last`, `pin_memory`, non_blocking copies.
- Mixed precision for the plain SGD forward/backward (`--amp`, fp16 autocast + GradScaler) is
  allowed ONLY if it is applied identically to every arm and is OFF inside all VNA/J/J_E/CG/TINY
  computations (SPEC §1.1). Default: off for this Phase-0 notebook unless you measure ≥1.5× speedup;
  record the decision. If on, add a test that VNA code runs with autocast disabled even when called
  inside an autocast context.
- In `signal_curve.py`: cache per-checkpoint quantities shared across sites (batches, logits, g),
  avoid recomputing forward passes from the network input for J products if the block input can be
  cached (forward only from the block onward) — only if exact; add a test that it equals the
  full-network product.
